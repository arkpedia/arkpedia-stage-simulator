# Native buff compiler expansion

Approved scope: expand the existing compiler into reusable validated data programs. Keep source compilation out of browser startup and preserve existing operator programs.

1. Extend the common template frontend with an explicit build-time dialect. Compile reviewed native predicates, conditional branches, immediate release, child buffs and fixed sourced HP loss into a bounded JSON graph. Refuse unknown fields and inactive unsupported branches.
2. Validate and execute those graphs in one small selected runtime. Preflight the whole graph and all blackboard operands before mutation; reuse existing buff clocks, HP loss and blocking operations. Keep source, owner and modifier target distinct.
3. Migrate Gnawbeast bleed and Zealous Extra conditional release to the compiler. Retain old compiled-plan compatibility. Keep source admission gates strict and independent from execution support.
4. Store shared program graphs once in the existing component store and hydrate only the selected stage's program references. Validate programs during runtime preparation before combat.
5. Exercise negative compilation, ownership, timing, refresh and cleanup cases; run source/runtime parity and all available stage smoke checks; inspect desktop/touch loading. Commit and push reviewable batches regularly.

Initial limits: only reviewed node/flag combinations; no arbitrary scripts, summons, environment controllers, derived buffs, stat modifiers or inferred damage behavior. Later additions require one opcode contract plus source fixtures rather than another enemy-specific interpreter. Program support alone never grants admission to a source record.
