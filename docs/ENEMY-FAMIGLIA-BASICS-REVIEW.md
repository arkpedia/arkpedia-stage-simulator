# Famiglia Soldiers and Intimidators

Both Soldier variants and both Intimidator variants now compose the shared native melee clock and a reusable selected death-SP program. A killed Soldier grants 20 SP, an Elite Soldier 35, and either Intimidator 80 to the selected device tagged vgctrl. The original global selector allows either side, device category only and one recipient. An unrelated stage has no matching receiver and therefore receives no gift.

SP flows into the receiver's existing gauge through a small registered adapter or ordinary SkillRuntime. No parallel gauge is created. The receiver owns its capacity and active-state policy, while the adapter checks battle/deployment identity and SP refusal. The native ModifySp dialect is bounded, target-bound and positive; altered ratio, mask, force and subtraction policies are refused. Services and all operands are checked before any effect.

The Intimidators' native persistent TAUNT_LEVEL addition is applied separately from the database's base priority: base one plus the native modifier one. Removing the owned passive removes that modifier and its death gift. Soldiers retain their independent killed-result attachment. Removing either owned attachment preserves foreign same-key instances and leaves the other attachment's behavior independent. Leakage does not grant SP or record a killed result; silence does not disable these native passives.

Admission checks the complete talent/handbook shape, ordinary melee packet and original clocks, passive and selector bindings, the exact death program and reward buff, the retained SP template and killed-log contract. The previous named-crew DeathRattle behavior remains independently routed. Program consumers now explicitly declare supported external services, so an energy-only component cannot accept an SP program and discover the mismatch after actor mutation.
