# Thumpy source and public combat review

Thumpy (`char_4235_thumpy`) is available through the regular-stage squad and support paths with all three selected source skills. The normal preview has 389 pinned source forms, 849 skills and 889 models, with 42 forms remaining. Modules, original native effects/audio and game-frame/pixel parity remain unverified. Arkpedia app dev and production remain untouched.

The foundation contains 467,378 bytes, SHA-256 `9a727b44984f8286d4dd8921a0c2e4e6f47e1ac62f8407bca6be0a7b421e69da`. It is pinned to CN commit `a550f5e048bb94e7cdefc6eb97a4091f0c4c7add`, client `26-09-22-07-47-20_6c71fa`. Five original bundles retain 123 owner/skill components and fifteen transitive templates. No referenced projectile/token graph or unresolved template remains.

Independent audits reproduce seven original outputs and reject 29 altered source or premature-approval claims on Node 22 and 24. Forty-three source-selection and exact-clock checks pass on both versions, covering all thirty skill ranks, promotion/potential/trust, visible and empty native talent candidates, original component identities, locked inputs and animation tracks.

The source has ordinary Attack plus three distinct Begin/Loop/Idle/End families. S1 Begin is approximately 0.166667 seconds, S2 Begin 0.666667 and S3 Begin one second; every End is approximately 0.166667. S2/S3 tile-cast abilities use fixed time with native slow-down and original Begin markers. Ordinary/mode attack abilities retain native maximum animation scale `-1`, unlike Crackborne's cap of `1`; ordinary selectors also retain their block-count-related operands. These retained inputs are implemented under the explicit adapter mappings below; they do not certify compiled native timing/targeting behavior.

The first visible talent scales elemental intake and branches on a physical-output target's WATER recovery state, reducing its recovery cooldown or applying injury. The second visible talent uses source-specific recipient marks and pre-burst dispatch to grant DEF stacks and capped barriers. Empty native talent candidates remain present. S1 retains ATK/DEF and push operands; S2/S3 have separate tile setup, repeat intervals, trigger-versus-damage injury keys, and mode switching. Native stack-cap/creation dispatch and casting/FSM order remain unverified. The local resource contract described below makes its mappings explicit.

Original owner artwork is verified separately: recipe-bound native pointers, unchanged source files, decoded pixels and PMA. Artwork audits reject 33 altered claims on Node 22 and 24. Thirty-one clips per viewport render in thirty-two desktop/emulated-phone captures with no errors or failed resources. Desktop S3 Begin and mobile S2 Loop were visually inspected. SD tests pass 66 checks and validate 3,013 models, scenery and native effect packages on both Node versions. Only two Thumpy metadata rows change; six raw files and the other 3,011 models remain unchanged. The SD metadata is merged through PR 29 at `06a53259a294988ccdb99324c8bb5a3fcbfe058e`; tested/proposed/final tree `1144630a870e2ec4ae9da43cf3a0461e4fdc456d` matches. Modules, native effects/audio and original game-frame/pixel parity remain unverified. Arkpedia app dev and production remain untouched.

The selected talent has a thirty-stack DEF cap while the raw generated buff retains twenty, and the shield template has an initial increment plus an explicit burst-listener trigger path. The source test preserves both records. The diagnostic resource contract uses the selected thirty-stack cap and one selected shield increment per burst, coalescing initial/forced dispatch. This is a stated local interpretation of selected talent behavior, not proof of compiled blackboard/creation priority; it does not certify compiled native priority.

The resource layer implements elemental intake, current-ATK physical injury and erosion cooldown reduction; source-derived recipient marks; permanent DEF and capped barriers; all three selected mode buffs; S2 glue recipient clocks and other-operator injury; S3 pre-burst DEF cuts and conveyor movement. Parent rejection/removal, recipient leave/reentry, source epochs, source retirement and reentrant callbacks are covered. Marks are attached before the local talent rider; accepted shield/floor hits still count, while cancelled/dodged source output, HP loss, gauge receipts and sourceless credit do not fabricate marks. Glue's recipient-side modifier intentionally does not filter later dodge/cancellation, matching the retained native node's lack of that filter.

Field intervals use the selected hidden-talent transfers, not the raw placeholder one-second child value. Own field physical damage retains the original first-talent injury; the skill's zero trigger operand belongs to the separate hidden talent and is not used to erase the visible talent. Captured field bodies and own blockees share one source-specific child. Immediate entry pulses, independent periodic clocks, current hidden/invulnerable/invisible checks, current ATK, S2 Slow and cleanup are tested. The caller still must supply independently reviewed S2 flood/seed and S3 line tiles at original cast releases; the resource API itself does not choose tiles or pretend to execute the cast.

S3 moves unblocked ground bodies at the selected speed, checks live weight and retained `immune_shu_blink` / `immune_yu_blink` guards, and preserves independent field damage on movement-immune recipients. The shared collision/route-aware mover's force/static-body rules are an explicit adapter limit, not certified native conveyor semantics. The extra DEF cut is source-nonderived and survives field/source removal.

Eighty-one focused resource checks plus the source/exact-clock, adjacent defender, elemental medic and slow-down regressions pass on Node 22 and 24: 332 tests per version, zero failures. The original attack/cast controller described below and its public integration are now implemented; full-suite and hosted verification remain separate.

The selected controller binds original Front/Back attacks and all three skill families. Default and S2 attacks retain one input because their native attack ability has a null selector binding; S1/S3 bind their explicit block-cap selectors and capture own blockees. The original S2/S3 sequence lists the stat-buff ability before the tile-cast ability, with `alwaysNext` and `forceNextIfCastFail` both enabled. All three stat modes therefore start at activation in this adapter. S1 uses its unscaled root Begin. S2/S3 use fixed Begin clocks with current native slow-down and original release markers, independently of ASPD. Area selection is sampled at the marker, then captured. Duration/SP accounting starts at activation. Brief control epochs cancel only unreleased tile work; already released fields/stat modes remain, matching the root's retained stop-affect-on-interrupt policy. The mode-before-tile sequence is source-backed; detailed compiled callback order remains unverified.

S2 maps the native traversal enum `1` to a feet-first breadth-first patch, using the retained forward/left/right offsets, five-cell cap, valid neighboring fallback seeds and no expansion through invalid cells. The compiled enum/seed/mask semantics are an explicit local interpretation. S3 filters the fixed five offsets in source range `4-1` independently. Neither selector alters terrain or invents replacement cells outside its defined policy.

Ordinary windup uses the input-time interval and uncapped source animation scale. Native slow-down is already included in ASPD and is not multiplied twice. Positive ordinary cooldown survives cast/mode/End transitions. The only native End mixes are skill Idle to ordinary Idle; ending from a skill Loop does not fabricate a missing mix. S1 pushes independently of a dodged physical hit, using radial direction and the selected force operand; the retained `1` reduction maps locally to one level for off-axis/near targets relative to deployment facing. Compiled force-direction and distance-column/frame behavior remain unverified.
